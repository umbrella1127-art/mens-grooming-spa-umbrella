# 実ページの調査と、実ページ起点の戦略

引数: `$ARGUMENTS`（例 `<store>`。省略時は設定にある全店舗）

Salon Report は「何本・何件」という**数**しか教えてくれない。
お客さまが実際に見て決めているのは**そこに何と書いてあるか**で、そこはレポートに出てこない。
このコマンドは実ページを見て、その中身から戦略を立てる。

## 手順

### 1. 現状確認

```bash
python scripts/hpb/context.py --store <store>
python scripts/hpb/query.py "SELECT MAX(observed_at) 最終観察日, COUNT(*) 件数 FROM page_observations WHERE store='<store>'"
```

最終観察日が**2週間以内なら調査は省略**して手順3へ進んでよい（ページはそこまで頻繁には変わらない）。
ユーザーが「今すぐ見て」と明示した場合は必ず調査する。

### 2. 実ページ調査（`hpb-page-scout` に委譲）

プロンプトに必ず含める:

- 対象店舗コードと `hpb_cd`（`stores テーブル（scripts/hpb/config.json → db_migrate.py）` にある）
- 観察日（今日）
- **全クーポンを1本残らず記録すること**（`--position` に表示順、`--label`、`--value-num` に価格）
- **口コミの最新投稿日は、全件の投稿日を取って最大値を求めること**
  （一覧の先頭は投稿日順ではない。ここを誤ると判断が丸ごと狂う）
- 競合を2〜3店、同じ観点で見ること
- **分析も解釈も提案もしないこと。事実だけを記録すること**

### 3. 実ページ起点の戦略（`hpb-strategist-page` に委譲）

プロンプトに必ず含める:

- 対象店舗・月号（今日の属する月）
- `page_observations` を一次情報にすること
- **1つの論点につき 守り／標準／攻め の3案**を `--lens page` で `strategy_options` に登録すること
- `--rationale` に**実ページで見た事実を必ず引用**すること（obs番号か原文）
- 表示名の変更案は**そのままコピペできる完成形**で書くこと
- 攻めの案には**撤退条件**を付けること
- 価格の上げ下げは価格担当の領分なので踏み込まないこと

### 4. 確認

記録は管理画面 `/admin/kpi/hpb` の「実ページで見てきたこと」に反映される。

## 報告に含めること

- **レポートの数字と実ページの中身が食い違っている点**（あれば最優先）
- 口コミの最新投稿日と、競合との差
- クーポンの実質本数（ダミー行を除いた数）と、棚の状態
- 出した案の一覧（論点・スタンス・タイトル）
- すぐ実行できるもの（並び替え・表示名変更は当日反映される）を明示する
