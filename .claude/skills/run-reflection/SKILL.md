# 振り返り（4層）の書き方

振り返りは、次の改善すべての材料になる。**作業の最後、完了報告の直前に1回だけ**書く。
書いた内容は、点検担当・知識整理担当・戦略担当・オーナーがそれぞれ読む。
読み手が違うので、4つの層を混ぜずに書く。

| 層 | 何を書くか | 誰が読むか | いつ効くか |
|---|---|---|---|
| ① 成果 `--output` `--url` | 何ができたか。通知・下書き・レポートのURL | オーナー | すぐ |
| ② やったこと＋自己診断 `--did` `--self-check` `--rules-ok` | 実際にやった手順と、手順書・絶対ルールを守れたか | オーナー・点検担当 | すぐ |
| ③ 仕組みの改善案 `--system` | 担当の定義・手順書・コード・ルール・データのどこを直せば、次回もっと楽に・確実にできるか | 点検担当（毎朝） | **次回すぐ** |
| ④ 事業の改善案 `--business` | 成果物そのもの（投稿の中身・時刻・見せ方・チャネル）をどう変えれば、お客さまが増えるか | 知識整理（週1）・戦略担当（月1） | **中長期** |

## ③と④を混ぜない

- 「手順書のこの一文が曖昧で迷った」「このSQLが毎回エラーになる」→ **③ 仕組み**
- 「朝の投稿のほうが読まれていそう」「このクーポン名は分かりにくい」→ **④ 事業**
- 迷ったら、「直す場所は `.claude/` や `scripts/` の中か（③）、お客さまが見るものか（④）」で分ける

## 書き方

```bash
python scripts/reflect/reflect.py add --channel <threads|hpb|site> --agent <自分の名前> \
  --run-ref <工程:日付 または hpb:analysis_runs:<run_id>> \
  --output "<① 何ができたか1〜2行>" [--url <成果のURL>] \
  --did "<② 実際にやった手順を短く>" \
  --self-check "<② 手順書どおりにできたか。飛ばした手順・迷った点・ルールの確認結果>" \
  --rules-ok yes|no \
  --system "<対象>|<ファイルや項目>|<提案>|<理由>"   # 何件でも。無ければ --no-system
  --business "<分類>|<提案>|<理由>"                   # 何件でも。無ければ --no-business
```

- `--run-ref`: Threadsは `threads:<工程>:<日本時間の日付>`（例 `threads:validate:2026-09-22`）。HPBは `hpb:analysis_runs:<run_id>`
- `--system` の対象: `agent`（担当の定義）/ `skill`（手順書）/ `code`（scripts）/ `rule`（絶対ルール・禁止表現）/ `data`（DBの中身）
- `--business` の分類: `content`（中身・言葉）/ `timing`（時刻・頻度）/ `offer`（メニュー・クーポンの見せ方）/ `channel`（どこに出すか）/ `other`
- 改善案が無ければ **`--no-system` / `--no-business` を必ず付ける**（付けないと記録できない。書き忘れと区別するため）
- 1回の実行で無理に出さない。**実際に困ったこと・データで見えたことだけ**を書く。「念のため」の案は書かない
- **`--rules-ok no` のときは、何を守れなかったかを `--self-check` に具体的に書く**（隠さない。点検担当が直す材料になる）
- 絶対ルール（医療的断定・煽り・未確定価格・個室・電話番号・Hot Pepper掲載・実売上の転記）に触れる改善案は出さない

## 良い例

```bash
python scripts/reflect/reflect.py add --channel threads --agent threads-strategist \
  --run-ref threads:validate:2026-09-22 \
  --output "今日の3本を draft 登録（p40疲労・p47睡眠・p53肩こり）。勝者なし" \
  --did "前日3本を実測→全て反応0→勝者なし→知識を読んで今日の3本を作成" \
  --self-check "禁止表現チェック3本ともOK。日付はJSTで書いた。手順Cの勝者の記事化依頼は該当なしで省略" \
  --rules-ok yes \
  --system "skill|.claude/skills/threads-validate/SKILL.md|反応0が3日続いたときの手順を足す|勝者が決まらないと学びが1件も増えず、同じ型を繰り返してしまう" \
  --business "timing|8:00枠を7:00に早めて1週間試す|3日とも8:00枠だけ閲覧が付いている"
```

## やってはいけないこと

- 振り返りを書かずに完了報告する
- ③と④を1つの案にまとめる
- 自分で自分の改善案を「適用済み」にする（適用・却下は読み手の担当かオーナーが付ける）
