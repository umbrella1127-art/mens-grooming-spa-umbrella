# 中間チェック（月の途中でペースを見る）

引数: `$ARGUMENTS`（省略時は設定にある店舗が1件ならそれを使用。複数ある場合は明示・今月）

月次のフル分析（`/hpb-run`）は締め後にしか回らないため、**打った施策の結果が分かるのが翌月**になる。
このコマンドは月の途中で新規獲得のペースだけを見て、**月内に軌道修正できるようにする**もの。

## 目的とKPI

見るのは **新規獲得数** と **CPA（掲載料÷新規数）** の2つだけ。
それ以外の指標は月次のフル分析で扱うので、ここでは深追いしない。

## 手順

### 1. 最新のSalon Report PDFを用意する

サロンボードから**今この時点の**Salon Report をダウンロードして
`data/hpb/<store>/inbox/` に置いてもらう（ユーザーに依頼する）。
締め前なので当月は途中集計になる。それでよい。

**★ inbox にあるPDFの月号を必ず確認する。**
ファイル名の先頭4桁が月号（例 `2607_<store>_<hpb_cd>.pdf` = 2026年7月号）。

- **今月と違う月号のPDFを、今月の途中経過として読んではいけない。**
  過去月の確定値を「今月ここまで」として記録するとペース判定が丸ごと狂う
  （7月の月間8人を、8月の10日時点の数字として記録してしまう）
- 過去月のPDFが混ざっていたら、それは確定月のレポートなので
  **`/hpb-collect` の通常の取り込み**に回す。`hpb_kpi_snapshots` には入れない
- 今月のPDFが無ければ中間チェックはできない。その旨を伝えて終える

### 2. 新規獲得数を読み取る

PDFの1ページ目「新規/リピーター」行の**当月列**を読む。
`parse_salon_report.py` は13ヶ月分を上書きしてしまうため、
**中間チェックでは実行しない**。PDFをReadで直接読んで当月の値だけ取る。

読む値: 新規獲得数・NET予約数・売上・CVR・ACR・クーポンメニューPV・予約完了PV

### 3. スナップショットとして記録する

```bash
python scripts/hpb/pace.py record --store <store> --month <YYYY-MM> \
  --as-of <取得日 YYYY-MM-DD> --new <新規数> --reservations <予約数> \
  --sales <売上万円> --cvr <CVR> --acr <ACR> \
  --pv-coupon-menu <クーポンメニューPV> --pv-reserve-done <予約完了PV> \
  --source salon_report
```

**確定値ではないので `hpb_monthly_kpi` には入れない。** `hpb_kpi_snapshots` に分けて持つ。
これを毎月同じ頃に続けると、翌月から「先月の同じ日数時点」と実測どうしで比較できる。

### 4. ペースと着地見込みを判定する

```bash
python scripts/hpb/pace.py check --store <store> --month <YYYY-MM>
```

出力の読み方:
- **同じ日数時点での比較** — これが最も信頼できる。過去スナップショットがあれば最優先で見る
- **日割りした参考比較** — 月内で来店が偏る（連休・給料日後など）ため、あくまで参考
- **着地見込み** — 必ず幅で見る。「同じペースが続く」は上限であって予測ではない

### 5. 判断して、必要なら月内に動く

| ペース判定 | 取るべき行動 |
|---|---|
| 平年を上回っている | 今の施策を続ける。何が効いているか特定して来月へ引き継ぐ |
| 平年並み | 様子見。ただし目標CPAに届かないなら1つだけ手を打つ |
| ⚠ 平年を下回っている | **月内に手を打つ。** 即効性のあるものから順に下記を検討 |

月内に効く手（効果が出るまでが速い順）:
1. クーポンの並び替え・表示名変更（即日反映、管理画面のみ）
2. 予約が入っている価格帯のクーポンを目立つ位置へ
3. 勝ちパターンのブログを追加投稿（当店は「体の不調・疲れ起点→ヘッドスパ」）
4. 口コミ依頼の強化（遅効性だが土台になる）

**未検証の戦略があれば、それが実行されているかも必ず確認する**:
```bash
python scripts/hpb/query.py "SELECT id, month, priority, title, target_metric, baseline_value, target_value FROM strategies WHERE store='<store>' AND status IN ('proposed','adopted') ORDER BY priority"
```
実行されていない施策があれば、それを促すのが最も効果的な打ち手。

## 報告に含めること

- 今月ここまでの新規獲得数と、平年ペースとの差
- 着地見込み（幅で）と、そのときのCPA
- 月内に打つべき手（あれば1〜2個に絞る。あれもこれも言わない）
- 前回提案した施策で、まだ実行されていないもの
